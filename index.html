Go · Next.js · PostgreSQL · Playwright · GitHub Actions

MVMed Management

QA Engineer Intern · Apr–Jul 2026 · latest internship project

Private repository

Problem

Medical equipment management: a Go API over Supabase PostgreSQL with a Next.js client, covering auth, RBAC, tenders, capability matching and audit logs. The Go API is the sole enforcement point for JWT issuance, refresh rotation and permissions.

Testing strategy

Test suites per package: auth service, refresh and logout, permissions, JWT, audit, tender service and status transitions, plus API-level authz, middleware and error tests against the OpenAPI spec.

Automation approach

Playwright end-to-end tests run against a production build on an isolated port, with database-dependent specs skipped rather than failed when no seeded database is present. Postman collections stay in sync via cmd/syncpostman.

Key result

A GitHub Actions pipeline that gates every push: gofmt, build, vet, go test ./..., sqlc drift check, a drop/up/down/up migration smoke test with guards against running on a populated database, then lint, build and Playwright.

Syncraft

QA automation / backend engineer

Repository ↗

Problem

Real-time plain-text collaboration where the server is a relay and store, not the conflict resolver: correctness comes from a CRDT engine, and deterministic replay and convergence are non-negotiable.

Testing strategy

Canonical invariants, protocol spec and use case catalog written first, then tested per layer: CRDT engine and model, protocol messages, persistence store, editor, and reconnect client.

Automation approach

A dedicated QA package: a harness suite exercising reconnect, replay, duplicate delivery and out-of-order operations, plus a performance suite, alongside tests for the browser demo server.

Key result

A runnable browser demo (go run ./cmd/demo-server) with release evidence, known limitations and an offline queue documented against the spec.

Task Management System

Backend engineer / QA-focused engineer

Repository ↗

Problem

A multi-user task, project and user management platform on an MVC Express backend with MySQL and Sequelize, JWT auth, roles and permissions, and WebSocket notifications.

Testing strategy

Unit and integration tests split by layer, with role and permission seeders giving every run the same authorization fixture to test against.

Laravel · REST API · Postman · Collection Runner

Book Store

API testing / backend engineer

Repository ↗

Problem

A Laravel book catalogue that imports from two third-party sources — Gutendex and Google Books — behind its own authentication.

Testing strategy

A committed Postman collection and environment covering register, login, logout, search, detail and import across both providers, so the API is testable on a fresh clone.

Automation approach

A separate automation-flow collection runs end to end in the Collection Runner: register a random user, capture the token into the environment, import from both sources, verify the results, then clean up and log out.

Key result

A repeatable regression pass over the whole authenticated import flow that leaves no test data behind, documented in the collection's own README.
